# 雪痕 · AI NPC 互动剧情框架

![雪痕](content/assets/cg/kv.webp)

[English](README.en.md)

**会记住你的 AI 互动短剧。** NPC 有自己的设定、秘密和剧情，但你和他们说的每一句话都只属于你：他们记得你说过什么，会把听来的事转告给别人，会在关键的那场戏里，把你当初的原话说回给你。

这个仓库包含两样东西：

1. **一套框架**：让大模型扮演有记忆、有秘密、会按剧本走、又能自由聊天的 NPC。零依赖（只用 Python 标准库），任何兼容 OpenAI Chat Completions 接口的模型都能接。
2. **一个完整的示例故事《雪痕》**：关外、大雪封山、客栈、一桩十年前的旧案。6 章，3 个可以自由对话的 NPC，3 个结局，一局大约一个小时。

---

## 示例故事《雪痕》（不剧透）

> 关外，雁回镇。你在镇口开了十年客栈，镇上的人都说你脾气好、手稳、算账快。没有人知道你是谁。
>
> 今冬的头一场雪落下那晚，一个少年踹开店门，剑尖指着柜台："谁是一刀雪？"
>
> 当夜，大雪封山。第二天，店里死了人。

- **你**：客栈掌柜。性别自选，名字、店名自取。
- **谢不归**：来找"一刀雪"报仇的少年剑客。
- **何忍冬**：镇上医馆的姑娘，她爹死在了你的后院。
- **严守正**：六扇门名捕，追了"一刀雪"十年。

悬疑、掉马、虐。每章一段剧情，然后你有一盏灯的时间，去找他们说话（三个人共 12 句）、做点经营和调查、决定要不要露一手。最后一章，你要当着所有人指认凶手。

## 框架能做什么

| 能力 | 说明 | 《雪痕》里用在哪 |
|---|---|---|
| **分层心事** | NPC 的秘密按章节解锁。没解锁的部分根本不进提示词，模型不知道，所以说不漏 | 凶手在自由对话里永远不知道自己是凶手，只在结局揭晓时才拿到"真相" |
| **记忆整理** | 每次谈话后，NPC 写日记、更新对你的看法、记下关于你的事实、约定、讲过的事 | 每个人下次见你时都记得上次聊了什么 |
| **原话摘录** | 整理记忆时摘录你的原话（只收真的出现在对话里的句子），按话题存好 | 掉马那场戏，少年会说"那天你还跟我说……"，用的是你自己的话 |
| **NPC 之间传话** | 一个 NPC 会把你说的话转告给另一个，带来源和可靠程度 | 你对医馆姑娘说的话，可能会传到名捕耳朵里 |
| **心声** | 每轮多一行"心里话"，可以一直显示、信任够了才显示，或者从不显示 | 少年一直看得见；姑娘要等她信任你；名捕永远"看不透" |
| **生活推演** | 每章开始，按剧本锚点让模型推演每个 NPC 这段时日在做什么，会把你们最近的事算进去 | 每个玩家看到的 NPC 生活都不一样 |
| **导演场景** | 关键戏：场景 + 必经事件 + 关键台词，模型和你演 2–5 轮；可以按条件分版本 | 冬至包饺子；腊八后的医馆，按姑娘对你的信任走不同版本 |
| **专属台词** | 写死的剧情里留一个空，由 NPC 从对你的记忆里写一句 | 掉马、结局里那几句只属于你的话 |
| **回合预算** | 每章自由对话的轮数，可以几个 NPC 共用；快用完时 NPC 会自然地收尾 | 一盏灯，三个人，12 句——找谁说话本身就是选择 |
| **回复选项** | 按玩家人设生成可点的选项，人设也按章节解锁，选项不会替你提前说破 | |
| **事件、变量、线索** | 经营、调查、有选择的事件；剧情变量；线索簿 | "露一手"：出手会被店小二看见、传出去 |
| **指认与多结局** | 选凶手、摆证据，按证据分量和关系决定结局 | 三个结局 |
| **全服消息** | 一个玩家世界里的事件可以用到其他真实玩家的信息 | 江湖传言里出现的客栈名，是别的玩家起的 |
| **防剧透检查** | 按章节把每个 NPC 的提示词拼出来，检查不该出现的字有没有提前混进去 | `tools/check_content.py` |

## 30 秒跑起来

只需要 Python 3.10 以上，不用装任何依赖。

```bash
git clone <这个仓库> ai-npc-drama
cd ai-npc-drama
python3 run.py
```

打开 <http://127.0.0.1:8800>。macOS 上也可以直接双击 `start.command`。用 Docker 的话：

```bash
docker build -t ai-npc-drama . && docker run -p 8800:8800 -v "$PWD/local-data:/data" ai-npc-drama
```

默认是**模拟模式**：不调用模型，对白是固定的占位句子，只用来看流程。要接真实模型，可以在页面右上角点"模型"，填服务地址、模型名和密钥；也可以用环境变量启动：

```bash
OPENAI_API_KEY=sk-... NPC_BASE_URL=https://api.openai.com/v1 NPC_MODEL=你的模型名 python3 run.py
```

任何兼容 Chat Completions 的服务都可以接，比如 DeepSeek、通义千问、智谱，或者本地用 vLLM、Ollama 起的服务。各项配置的含义见 [docs/配置说明.md](docs/配置说明.md)。

> 剧情体验依赖模型的中文角色扮演能力，建议用你手头最强的模型。

## 写你自己的故事

框架不认识《雪痕》。剧情、人物、世界、事件、线索、结局、界面文案，全部在 `content/` 里。

```bash
cp -r content my-story        # 从示例改起
# …改 my-story 里的文件…
python3 tools/check_content.py my-story   # 检查引用、条件、能不能凑够证据、有没有剧透
CONTENT_DIR=my-story python3 run.py
```

怎么写，见 [docs/内容包写作指南.md](docs/内容包写作指南.md)。

## 放进真实游戏

`npc/` 是运行时，不认识章节、CG、事件这些东西，只收"阶段、事件、记忆、导演场景、专属台词"这几种指令。`host/` 是 Demo 里模拟"游戏服务器"的那一层。放进正式游戏时，换掉 `host/`，在你自己的服务器里调用运行时，数据库换成你自己的实现即可。详见 [docs/架构说明.md](docs/架构说明.md)。

## 目录

```
npc/            运行时（通用）：内容加载、提示词、对话、记忆、存储、模型网关
host/           Demo 宿主：剧情导演（story.py）、HTTP 服务（server.py）、页面（web/）
content/        示例故事《雪痕》的内容包；美术素材放在 content/assets/
tools/          check_content.py：内容包检查与防剧透检查
tests/          测试（模拟模式，不联网）
docs/           架构、内容包写作指南、配置、部署、美术提示词、示例故事的设计说明（含剧透）
```

## 测试

```bash
python3 -m unittest discover -s tests          # 全部测试，模拟模式，不联网
python3 tools/check_content.py                 # 只检查内容包
```

设置 `TEST_DATABASE_URL=postgresql://…` 会在 PostgreSQL 上再跑一遍剧情测试。

## 成本

每个玩家玩完一局，大约调用模型 200–250 次：自由对话每轮 2 次（对白 + 回复选项），加上导演场景、记忆整理、每章的生活推演和专属台词。提示词的前半部分（世界、人物本）固定不变，能吃到服务商的提示词缓存。

## 美术素材

示例故事的插画和头像在 `content/assets/` 里，用 AI 绘图工具按 [docs/美术提示词.md](docs/美术提示词.md) 生成，格式是 webp（png、jpg 也认）。想换成自己的图，同名替换即可，刷新页面就生效；删掉图片，页面会退回文字场景卡和代码画的临时头像。
