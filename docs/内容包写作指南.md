# 内容包写作指南

框架不认识任何具体的故事。人物、世界、章节、剧情、事件、线索、结局、界面文案，都写在内容包里。这份指南讲怎么写一个自己的内容包。示例《雪痕》就在 `content/` 里，边看边对照最快。

```bash
cp -r content my-story
python3 tools/check_content.py my-story      # 写完先检查
CONTENT_DIR=my-story python3 run.py          # 用你的内容包启动
```

## 目录结构

```
my-story/
  pack.json             总配置：标题、玩家怎么建档、有哪些 NPC、对话预算、事件分组、界面文案
  world.md              世界常识：所有 NPC 每次都能看到
  player.md             玩家人设（分层）：只给"回复选项"的生成器看
  npcs/<id>/npc.json    人物的配置：名字、地点、表情、心声、初始交情、传话关系……
  npcs/<id>/bible.md    人物本：性格、说话方式、日常（每次都给模型）
  npcs/<id>/secret.md   心事（分层）：按章节解锁
  story/01.json …       每一章：CG、导演卡、章末钩子、每个 NPC 这一章的状态
  events.json           玩家在界面上能做的事：经营、调查、有选择的事件、消息
  clues.json            线索
  endings.json          指认与结局（可以没有）
  checks.json           防剧透规则（可以没有，强烈建议写）
  assets/cg/            CG 插画（可以没有）
  assets/avatars/       头像（可以没有）
```

`.md` 文件里的 `<!-- 注释 -->` 不会进入提示词，可以放心写作者说明。

## 写之前先想清楚的三件事

1. **谁知道什么、从哪一章开始知道。** 这决定了 `secret.md` 怎么分层。模型不知道的事，就不可能说漏。所以与其写"不要说出 X"，不如在 X 该解锁之前，让提示词里根本没有 X。
2. **哪些必须写死，哪些交给模型。** 关键剧情写死（CG 台词），或者用导演卡规定"必须发生的事"。模型负责"怎么说"和"你们之间独有的那部分"。推理类剧情的关键线索一律由剧本给出。
3. **玩家能在哪里留下痕迹。** 自由对话、导演场景、专属台词、事件。框架会把这些都记下来：日记、原话、听说的事。想让玩家感到"它记得我"，就在后面的剧情里留空位，让 NPC 把这些说回来。

## pack.json

| 字段 | 说明 |
|---|---|
| `title` / `subtitle` / `seal` | 标题、副标题、左上角印章里的那个字 |
| `intro` | 新建存档时显示的开场介绍 |
| `login_hint` | 线上模式输口令时的提示 |
| `player.intro` | **NPC 眼里的玩家是谁**，放进每个 NPC 的提示词。例：`"{名}，雁回镇镇口「{店名}」的掌柜……"` |
| `player.name` / `player.shop` | 建档表单的两个输入框：`label`、`placeholder`、`max`（最多几个字）。`shop` 是"玩家的据点名"，台词里用 `{店名}` 引用 |
| `player.genders` | 可选的性别，每个有一组占位符替换，例如 `{"{ta}": "她", "{姐哥}": "姐"}`。在任何文字里写 `{ta}`，都会换成这个玩家对应的字 |
| `player.avatars` | 玩家可选的头像：`id`（图片文件名）、`label`、`mark`（没有图片时临时头像上的字） |
| `npcs` | 可以对话的 NPC 的 id，按显示顺序排列 |
| `budget` | 每章自由对话的预算：`per_chapter` 全章共几轮，`per_npc` 每人最多几轮。一轮 = 玩家一句 + NPC 一句 |
| `groups` | 事件分组，按顺序显示：`id`、`limit`（每章最多做几件，`null` 不限）、`hint`（`{n}` 换成剩余件数） |
| `vars` | 剧情变量及初始值，例如 `{"马甲": {"start": 0}}` |
| `chapter_label` | 章节标签的格式，`{cn}` 中文数字，`{n}` 阿拉伯数字，`{season}` 时节 |
| `options.kinds` | 回复选项的分工（默认三种：追问、表态、带入自己），每种写 `kind` 和 `desc` |
| `options.world_brief` | 一句话描述这个世界，用来提醒选项生成器不要出现不属于这个世界的东西 |
| `gestures` | 对话下方那排"动作"按钮 |
| `rumors` | 江湖传言模板：`template` 里的 `{1}{2}{3}` 换成其他真实玩家的店名，不够就用 `fillers` 补齐。这是"全服共享信息"的一个例子 |
| `ui` | 界面文案，可以整体换成你的故事的口吻。键名见示例 |

## world.md

所有 NPC 每次都能看到的世界常识。**只写"人人都知道的事"**：地理、风俗、公开的历史、江湖传闻。只有某个人知道的事，写进那个人的 `secret.md`。

## player.md（玩家人设，分层）

只给"回复选项"的生成器看，NPC 看不到。用来让选项符合玩家角色的口吻，并且遵守玩家角色的秘密。

```markdown
## 影子
（一直给）我叫{名}……我的样子、口吻。

## 第1章起
（第 1 章起才给）我的秘密……规矩：除非"我"自己说破，选项里绝不能承认……

## 第4章起
（玩家在第 4 章的剧情里"想起"的事，到第 4 章才给）
```

玩家人设也分层，是因为玩家自己的记忆也会随剧情揭开（比如 CG 里"你想起"的段落）。选项不能替玩家提前想起还没想起的事。

**"第N章起"只写第 N 章开场前就知道的事**，再加上第 N 章 CG 里、导演场景之前就发生的事。导演场景里和之后才知道的，写进这一章的 `player_note`（选项生成器会看到最近几条手记），下一章再写进人设。不然在导演场景里，选项会抢在 NPC 前面把话说出来。

## npcs/<id>/npc.json

| 字段 | 说明 |
|---|---|
| `id` / `name` / `title` | id（文件名用）、名字、玩家对他的称呼（选项里用） |
| `card` | 人物卡上的一行介绍 |
| `place` / `place_desc` | 平时在哪里见他，以及那个地方的描述 |
| `closed_line` | 和他这一章的轮数用完时显示的话（不调用模型） |
| `from_chapter` | 从第几章起可以对话 |
| `expressions` | 表情：英文键（头像文件名后缀）→ 中文名（给模型看）。头像文件是 `assets/avatars/<id>_<键>.png` |
| `hidden_expressions` | 只在写死台词里用、不让模型选的表情（比如揭晓时的"冷笑"） |
| `inner` | 心声：`{"mode": "always"}` 一直显示；`{"mode": "trust", "min": 10, "label": "看不透她"}` 信任到 10 才显示；`{"mode": "never", "label": "看不透"}` 从不显示 |
| `bond_start` | 初始交情 `{"trust": 0, "warmth": 0}`。认识很久的人，亲近可以一开始就不低 |
| `quote_topics` | 整理原话时建议用的话题词，比如 `["一刀雪", "师父"]`。专属台词可以按话题找原话 |
| `relays` | 传话习惯：`[{"to": "另一个NPC的id", "from_stage": 3, "what": "你会把什么样的事告诉他", "certainty": "中"}]` |
| `option_kinds` | 和他说话时回复选项的分工（覆盖 pack 里的默认），比如对一个城府很深的人，加一种"周旋" |
| `var_notes` | 剧情变量到了多少时，在"这次见面"里补一句：`[{"var": "马甲", "min": 1, "until": 4, "text": "你听说……"}]` |

## npcs/<id>/bible.md（人物本）

每次都给模型，而且放在提示词最前面（能吃到缓存）。建议的段落：

- `# 名字`，紧接着 `## 你是谁`。模拟模式靠这两行认出人物名，请保留这个写法。
- `## 你的性格`、`## 你说话的样子`：附几句例句，并注明"只是为了找口吻，不要照搬"。
- `## 你愿意聊的事`：让 NPC 有话可聊，玩家不至于冷场。
- 身边的人：他眼里的其他角色。

**人物本里只写这个人从第一章起就知道、而且可以说的事。** 会随剧情变化的，写进 `secret.md`。

小心"否定句提醒"：像"你不会怀疑掌柜就是一刀雪"这样的句子，反而会把这个念头塞给模型。改成正面描述："在你眼里，掌柜就是个开店的。"

## npcs/<id>/secret.md（心事，分层）

```markdown
## 影子
（一直给）你有一件不愿说的事……被问起时怎么应对。**不要编造另一套来历。**

## 第2章起
（第 2 章起才给）你知道了……你此刻能说到哪一步。

## 真相
（只在结局的专属台词里、显式要求"揭晓"时才给）
```

写法：每一段都写清"你知道什么"和"你此刻能说到哪里"。

**凶手怎么写：** 心事里写"无辜版"，也就是他做过的每个动作，模型都知道，但拿到的是说得通、清白的理由。比如"封山前两天你就到了，在山神庙住了两夜；你不想让人知道，是因为你在暗中查访"。这样玩家当面质问他时，他能自圆其说，也不会说漏嘴。真相写在 `## 真相` 里，只在揭晓的那一句给。破绽只埋在剧本写死的线索里，推理才公平。

## story/NN.json（每一章）

```json
{
  "n": 2, "season": "大雪", "title": "雪痕", "gap": "第二天。",
  "final": false,
  "limits": {"经营": 0},
  "require_talk": true,
  "npcs": { "<npc id>": { ... } },
  "cg": { "title": "...", "image": "cg02.png", "phases": [ ... ], "gives": ["c1"] },
  "memory": { "<npc id>": "第一人称的一段记忆，CG 播完后写进他的日记" },
  "player_note": "写进玩家手记的一句话",
  "outro": { "phases": [ ... ], "gives": [], "memory": {}, "player_note": "" }
}
```

| 字段 | 说明 |
|---|---|
| `gap` | 距上一章过了多久，NPC 知道时间过去了 |
| `final` | 最后一章：不能再"进入下一段时日"，改为"指认" |
| `limits` | 覆盖这一章各事件分组的件数（比如被关起来了就不能经营） |
| `require_talk` | 进入下一章前，这一章是否至少要和人说过一轮（默认要） |
| `npcs.<id>.stage` | **这一章你们的关系**，包括称呼。每个可对话的 NPC 都要写 |
| `npcs.<id>.anchor` | 生活推演的锚点：`situation` 大状况、`must` 必须成立的事、`fallback` 推演失败时用的兜底（`mood`、`doing`、`on_mind`、`small_news`） |
| `npcs.<id>.situation` | 玩家这一章来找他时，"这次见面"里的补充说明 |
| `npcs.<id>.notes` | 有条件的补充说明：`[{"if": 条件, "text": "..."}]` |
| `npcs.<id>.place` / `place_desc` / `arrive` | 覆盖这一章见面的地点、描述和开场。比如玩家被关在柴房，是 NPC 来门外：`"arrive": "（{名}被锁在柴房里。你来到柴房门外。请你先开口。）"` |
| `cg` | 开场 CG，进入这一章时自动播放 |
| `outro` | 章末钩子：玩家点"进入下一段时日"时先播放。短剧式的悬念放这里。只能是写死的 script |
| `memory` / `player_note` | CG 播完（或章末钩子播完）后写进 NPC 记忆和玩家手记 |
| `gives` | 给玩家的线索 |

### CG 的段落（phases）

**写死的段落** `{"type": "script", "image": "可选", "lines": [...]}`，每一句：

| who | 显示 |
|---|---|
| `narr` | 叙述 |
| `head` | 居中的小标题（比如"第二天清晨"） |
| `me` | 玩家说的话 |
| `<npc id>` | NPC 说的话，带 `expr` 表情 |
| `memory` | "你想起"：画面褪色成回忆 |
| `card` | 剧情卡片：不能对话的角色出场，带 `name` |
| `other` | 不能对话的角色说的话，带 `name` |
| `tip` | 给玩家的提示 |

每一句都可以加 `image`（从这一句起换图），也可以加 `if`（条件成立才出现）。

**专属台词**：在 script 里放一句

```json
{"who": "xie_bugui", "slot": "ch5_xie", "topics": ["一刀雪"],
 "instruction": "他想起这个冬天和掌柜聊过的一刀雪。从记忆里挑一句掌柜亲口说过的话……一到两句。"}
```

播放到这一句时，NPC 会从他对这个玩家的记忆里写一句：日记、事实、听说的事，以及按 `topics` 找出来的原话。结果会缓存，回看时不变。揭晓用的台词加 `"reveal": true`，模型这时才拿到 `## 真相`；加 `"expr"` 可以固定表情。

**导演场景** `{"type": "director", "npc": "...", ...}`：

| 字段 | 说明 |
|---|---|
| `scene` | 场景（从 NPC 的视角写，"你"是 NPC） |
| `player_state` | 玩家此刻的状态。NPC 只能从玩家的言行里察觉，不能说破 |
| `beats` | 必经事件，按顺序。模型每轮回报哪些已经发生，最后一轮会把没演完的补完 |
| `key_lines` | 关键台词，到了时机原样说出 |
| `rounds` | 演几轮（2–5 比较好） |
| `branch` | 分支说明，比如"如果玩家说出 X，你不信" |
| `option_hint` | 给回复选项的特别要求，比如"三个选项里要有：沉默" |
| `situation` | 补充说明。常用来提醒"这场戏发生在什么时刻，之后的事此刻都还没发生" |
| `stage` | 这场戏里"这一章的你们"用这一句，代替这一章 `npcs.<id>.stage`。章里的 stage 往往写的是 CG 之后的关系，戏里用会抢跑 |
| `gives` | 演完给的线索 |
| `variants` | **分版本**：`[{"if": 条件, "beats": [...], "gives": [...]}, {"else": true, ...}]`。进入这一章时就按条件选定版本，之后回看也不变 |

## events.json

```json
{"id": "inv_temple", "group": "调查", "chapters": [3, 4], "once": true,
 "label": "去镇外的山神庙看看", "note": "玩家看到的结果（写进手记）",
 "gives": ["c3"], "if": {"not": {"clue": "c3"}},
 "knows": {"he_rendong": {"how": "seen", "text": "她怎么知道这件事"}},
 "public": "写进'近来的消息'，所有 NPC 都能听到",
 "set": {"马甲": 1}}
```

| 字段 | 说明 |
|---|---|
| `group` | 属于 pack 里的哪个分组 |
| `chapters` | `[起, 止]`，含两端 |
| `once` | 整局只能做一次（默认每章各能做一次） |
| `if` | 出现的条件 |
| `knows` | 哪个 NPC 怎么知道这件事：`how` 为 `seen`（亲眼看见，可靠程度高）、`heard`（听 `source` 说，可靠程度 `certainty`）、`none`。键写 `"*"` 表示当时所有能对话的 NPC |
| `choices` | **有选择的事件**：`[{"id": "act", "label": "出手", "note": ..., "knows": ..., "set": ..., "gives": ...}, ...]`，配一句 `intro` 讲眼下的情况 |
| `special: "rumors"` | 江湖传言（见 pack 的 `rumors`） |

## clues.json

```json
{"weights": {"2": "确凿", "1": "中", "0": "低"},
 "clues": [{"id": "c3", "title": "山神庙的炭灰和红穗子", "weight": 2,
            "against": ["yan_shouzheng"], "text": "...", "note": "可选的备注"}]}
```

`against`：这条线索能用来指认谁，`"*"` 表示指认谁都算。烟幕线索可以指向无辜的人，分量给 0。

## endings.json

```json
{"accuse": {"chapter": 6, "title": "...", "prompt": "...",
            "suspects": [{"id": "yan_shouzheng", "name": "严守正"}, {"id": "lei", "name": "雷镖头"}],
            "culprit": "yan_shouzheng", "pick": 3, "pass": 5},
 "bond": {"npc": "xie_bugui", "peak_until": 4, "measure": ["trust", "warmth"]},
 "parts": {"reveal": [ ...几个结局共用的台词... ]},
 "endings": [
   {"id": "A", "title": "长安", "if": {"all": [{"accused_right": true}, {"score": [">=", 5]}, {"bond": [">=", 18]}]},
    "phases": [{"type": "script", "include": "reveal"}, {"type": "script", "lines": [...]}]},
   {"id": "C", "title": "...", "if": "else", "phases": [...]}
 ]}
```

- 指认：玩家选一个嫌疑人，再选最多 `pick` 条证据。证据分量相加，只算 `against` 包含这个人（或 `"*"`）的线索。
- `bond`：结局用的"情分"。算法是"第 1 章到第 `peak_until` 章里的最高点"加上"最后一章里的变化"。中间那一段的下跌不算，适合"某一章里关系必然破裂"的剧情。
- 结局按顺序检查 `if`，第一个成立的就是结局；最后一个写 `"else"`。
- 台词里的 `{证据}` 会换成玩家选的线索标题，`{凶手}` 会换成玩家指认的人。

## 条件

用在 `if`、`notes`、`variants`、结局里：

| 写法 | 意思 |
|---|---|
| `{"trust": ["he_rendong", ">=", 10]}` / `{"warmth": [...]}` | 某个 NPC 此刻的信任或亲近 |
| `{"var": ["马甲", ">=", 2]}` | 剧情变量 |
| `{"clue": "c3"}` | 玩家有这条线索 |
| `{"done": "inv_temple"}` | 做过这件事 |
| `{"chapter": [">=", 3]}` | 当前章节 |
| `{"all": [...]}` / `{"any": [...]}` / `{"not": ...}` | 组合 |
| `{"accused_right": true}` / `{"score": [">=", 5]}` / `{"bond": [">=", 18]}` | 只在结局里用 |

比较符：`>=`、`>`、`<=`、`<`、`==`、`!=`。

## 占位符

任何会显示或进提示词的文字里都可以用：`{名}`、`{店名}`，以及 pack 里性别配置的那些词（示例里是 `{ta}`、`{姐哥}`）。结局台词里还可以用 `{证据}`、`{凶手}`。

## checks.json（防剧透规则）

```json
{"rules": [
  {"who": "yan_shouzheng", "never": ["你就是凶手"]},
  {"who": "he_rendong", "before": 4, "text": ["七日寒"]},
  {"who": "player", "before": 5, "text": ["让他恨你"]}
]}
```

`tools/check_content.py` 会按章节、按 NPC（以及每种性别）把自由对话的提示词拼出来，包括人物本、已解锁的心事、这一章的关系、补充说明，以及这个人的导演卡。然后检查：
- `never`：自由对话里永远不能出现（只有揭晓的专属台词可以用）；
- `before: N`：第 N 章之前不能出现；
- `who: "player"`：查回复选项生成器拿到的玩家人设。

每次改完剧情都跑一遍。

## 美术素材

放进 `assets/cg/` 和 `assets/avatars/`，文件名对上就会自动替换临时图。CG 建议 16:9；头像正方形，头部居中，页面上会裁成圆形。

## 写作建议

- **开场就进冲突，每章结尾留钩子**（`outro`）。玩家的耐心比你想的少。
- **自由对话要有话可聊。** 给每个人准备几个他愿意聊、而且聊得具体的话题；给他一点和玩家不同的看法。
- **让记忆回来。** 后面的剧情至少留一两个专属台词，让 NPC 说出玩家自己说过的话或做过的事。这是这套框架最打动人的地方。
- **一个人一种关系。** 示例里三个人分别是：你瞒着他、她怀疑你、他在套你的话。记忆在每种关系里起的作用都不一样。
- **关键线索交给剧本。** 模型可以帮玩家把线索想明白，但关键线索本身不能只靠模型临场说出来。
